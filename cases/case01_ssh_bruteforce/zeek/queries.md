# Zeek queries — Case 01 (real loopback capture)

All commands run from `cases/case01_ssh_bruteforce/` with `export TZ=UTC` and
`export PATH=/opt/zeek/bin:$PATH`. Logs were regenerated by
`tools/run_zeek.sh case01_ssh_bruteforce case01` from the verified
`raw/case01.pcap` (SHA-256 `771e90d7…0c99`). TSV and JSON are two separate Zeek
runs: **UIDs are run-specific and deliberately differ** between `zeek/tsv/` and
`zeek/json/`; join them by timestamp, ports and byte counts, not by UID.
Timestamps are epoch seconds (UTC). `T`/`F` in TSV are `true`/`false` in JSON;
`-` means unset.

## 1. Connection inventory

```bash
zeek-cut ts uid id.orig_h id.orig_p id.resp_h id.resp_p service duration conn_state history orig_pkts resp_pkts orig_bytes resp_bytes orig_ip_bytes resp_ip_bytes \
  < zeek/tsv/conn.log
```

Observed output:

```text
1794846054.608130	CF3dQ73otQFUMGzMMi	127.0.0.1	34416	127.0.0.1	22	ssh	0.120797	SF	ShADadFf	13	12	1227	1741	1911	2373
1794846054.939960	CPbK9Z6ezH8vbIQn1	127.0.0.1	34430	127.0.0.1	22	ssh	19.858788	SF	ShADadFf	18	24	1679	2077	2623	3333
1794846074.796806	CIkYPK3CLHxdbW23vh	127.0.0.1	54844	127.0.0.1	22	ssh	14.196392	SF	ShADadFf	17	23	1603	1977	2495	3181
```

Interpretation: exactly three connections, all `127.0.0.1 → 127.0.0.1:22`, all
`SF` (normal SYN/FIN handshake + close), all identified as `ssh`, all history
`ShADadFf`. No other ports, no `S0`/`REJ`/`RSTO` rows.

## 4. Authentication heuristic fields

```bash
jq -r '[.ts,.uid,.auth_success,.auth_attempts,.client,.server]|@tsv' zeek/json/ssh.log
```

```text
1794846054.60828	CgHhyT2I0wlVGC3eKk		0	SSH-2.0-libssh_0.12.2	SSH-2.0-OpenSSH_10.6p1 Debian-1
1794846054.940122	CIfbKF1grytdbJoJsl	false	5	SSH-2.0-libssh_0.12.2	SSH-2.0-OpenSSH_10.6p1 Debian-1
1794846074.796943	CTN7cCDZzdiA6CoFh	true	5	SSH-2.0-libssh_0.12.2	SSH-2.0-OpenSSH_10.6p1 Debian-1
```

**Caveat:** `auth_success` and `auth_attempts` are Zeek's SSH analyzer
heuristics, raised from encrypted SSH packet patterns (`ssh_auth_attempted` in
`base/protocols/ssh/main.zeek`), **not decrypted protocol content**. The short
session has `auth_success=-` / `auth_attempts=0`; long session 1 is `F`/`5`;
long session 2 is `T`/`5`. An empty field in `@tsv` output means unset/false
as shown. No username, password, command or host-side result is available.

## 5. Cross-tool byte comparison (commands used for the saved tables)

```bash
tshark -r raw/case01.pcap -T fields -E separator='|' \
  -e frame.number -e frame.time_epoch -e frame.time_utc -e ip.src -e tcp.srcport \
  -e ip.dst -e tcp.dstport -e tcp.stream -e tcp.flags -e tcp.len -e frame.len \
  -e tcp.seq -e tcp.ack -e ssh.protocol -e _ws.col.Info > tshark/frame_detail.txt
# sums grouped by tcp.stream and direction are in tshark/stream_bytes_tshark.txt
# comparison against conn.log is in tshark/stream_bytes_diff.txt:
# all 18 counters match (6 per connection x 3 connections)
```
